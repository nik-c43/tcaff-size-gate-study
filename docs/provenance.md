# Происхождение кода и результатов

## Репозитории и состояние

Исследование оформлено отдельным репозиторием, чтобы собственные диагностические скрипты, ручная разметка и интерпретация результатов были отделены от авторского алгоритма. TCAFF и CLIPPER подключены на закреплённых коммитах; история старого исследовательского каталога не переносилась. Согласно [протоколу сохранения источника](source_preservation.json), исходные файлы и окружения оставлены на месте, а служебная `.git` старого проекта не удалялась и не переинициализировалась.

| Компонент | Версия/назначение |
|---|---|
| [TCAFF](https://github.com/mit-acl/tcaff/tree/ff4ceab04b03fecabc4de9c9cbe7dbba4ab50df9) | `ff4ceab04b03fecabc4de9c9cbe7dbba4ab50df9`, `vendor/tcaff`, MIT |
| [CLIPPER](https://github.com/mit-acl/clipper/tree/e514dc29c273837ffdfeebbefbdcb2a93d970969) | `e514dc29c273837ffdfeebbefbdcb2a93d970969`, `vendor/clipper`, MIT |
| [ROMAN, историческая ссылка](https://github.com/mit-acl/roman/tree/6253bb9c6cc497acd4e3697727b5b9f34d53bf21) | `6253bb9c6cc497acd4e3697727b5b9f34d53bf21`, только документация аудита; не зависимость |

Файл `.gitmodules` содержит только TCAFF/CLIPPER и публичные HTTPS URLs. Репозиторий исследования доступен на [GitHub](https://github.com/nik-c43/tcaff-size-gate-study); ROMAN остаётся ссылкой на исторический аудит и в зависимости не входит. [Протокол проверок](validation.md) различает исходную подготовку и последующую редакторскую проверку опубликованной копии.

## Исходный код и границы адаптации

Чтобы сравнение размерного допуска не смешивалось с другими изменениями, весь алгоритм B0 остаётся в исходных submodules. Собственная копия demo находится в [src/demo_cpu](../src/demo_cpu), её [фактический diff](demo.patch) отделён от upstream. Изменены только три файла:

| Файл/функция | Изменение | Возможное влияние |
|---|---|---|
| `detections.py`, импорты | `TYPE_CHECKING`, отложенные аннотации для FastSAM/детектора людей | Запуск по готовым JSON без импорта сетей; `DetectionData` совпадает по AST |
| `alignment_results.py`, `update_from_tcaff_manager` | NaN guard до преобразования отсутствующей позы | Обрабатывает отсутствие оценки; основной метод GT совпадает по AST |
| `demo.py`, `main` | Захват предложений, карт, выходов и GT по env flags | Дополнительная память/время логирования; не меняет предложения или параметры |
| `demo.py`, вспомогательная оценка | Второй робот `i-1` заменён на фактический `j`/`other_name` | Исправляет вспомогательную метрику robot-to-robot; фильтр и основной GT не меняет |

`robot.py` и `tcaff_data_processory.py` совпадают с upstream байт-в-байт; основной GT-метод и `DetectionData` — по AST. Проверено исходным `tcaff_baseline_audit.source_audit`. Полный diff содержит также конечный перевод строки; не следует приписывать ему научный эффект. Копия MIT license TCAFF сохранена в demo.

Связь описания исследования с исходниками закреплена следующими функциями TCAFF:

| Утверждение | Файл и функции |
|---|---|
| RGB-D медиана и 2D-границы → метрические центр/размер | [depth_mask_2_centroid.py](../vendor/tcaff/tcaff/fastsam3D/depth_mask_2_centroid.py), `depth_mask_2_centroid`, `mask_depth_2_width_height` |
| Размерный допуск, XY, release-порог отбора решений | [tcaff_manager.py](../vendor/tcaff/tcaff/tcaff/tcaff_manager.py), `get_putative_assoc`, `get_frame_align_measurements` |
| MNO, возрастные веса и подгонка | [frame_aligner.py](../vendor/tcaff/tcaff/realign/frame_aligner.py), `clipper_mult_sols`, `associate_static_objects`, `compose_solution` |
| Квадрат уже квадратичной формы | [node.py](../vendor/tcaff/tcaff/tcaff/node.py), `mahalanobis_diff`, `nlml`: `0.5*(q**2+logdet(S)+p*log(2π))` |
| Исходный относительный GT | [alignment_results.py](../src/demo_cpu/alignment_results.py), `AlignmentResults.get_Tij_gt` |
| Независимая композиция и replay | [tcaff_baseline_audit.py](../scripts/original/tcaff_baseline_audit.py), `load_poses`, `replay`, `pose_error` |

Для q=0.5 исходный квадратичный член равен 0.25, для q=2 — 4: это не обычный Gaussian NLL, содержащий q. Расхождение с формулой статьи сохранено; его исправление — отдельный возможный эксперимент, не упаковка. B3 и расширение поиска относятся к истории, не обязательному runner B0.

## Архив выполненного кода и переносимость

Для сохранения связи с выполненными экспериментами [scripts/original](../scripts/original) содержит неизменённые собственные runners и диагностики с исходными SHA. Они ожидают старую структуру каталогов. Новый [prepare_workspace.py](../scripts/prepare_workspace.py) создаёт её **вне репозитория**, подключает внешние данные и закреплённые зависимости; алгоритм/конфигурации не редактируются. Меняется только путь к прежнему бинарнику в рабочей копии baseline audit, при совпадающем SHA. Исходный audit остаётся неизменным.

Новые `inspect_saved.py`, `read_annotations.py`, `render_saved.py`, `render_real_examples.py` обслуживают чтение/упаковку. `src/model_geometry.py` содержит пять прежних диагностических функций без изменения AST; `reproduce_model.py` убирает зависимость идеальной модели от приватных реальных карт. Размерные формулы и исходный gate совпадают. Это перенос существующей проверки, не новый алгоритм.

Другие старые исследовательские скрипты, включая требующие ROMAN, остаются в исходном проекте. Не все исторические эксперименты доступны к запуску из нового репозитория; их компактные результаты и ограниченный статус обозначены в отчёте.

## Происхождение чисел и изображений

Численные выводы и ручные ответы имеют собственную цепочку происхождения. [source_inventory.json](source_inventory.json) фиксирует исходный относительный путь, SHA и SHA переносимого файла. Метки/код перенесены байт-в-байт. В копиях численных JSON заменены только локальные абсолютные пути в строковой метаинформации; численные поля не правились. Сжатие traces — lossless; compact run metrics сохраняет вычисленные ошибки, доступность, времена и источник каждого из 420 файлов, исключая исходные карты/предложения/GT-позы.

## Окружение и время

Исходный snapshot: Python 3.12.3, NumPy 1.26.4, SciPy 1.17.1, clipperpy 0.2.4, GNU 13.3.0; CPU AMD Ryzen 7 7840HS, 16 логических CPU, около 14 ГиБ RAM; Linux x86_64, kernel 7.0.0-38-generic. При подготовке `/etc/os-release` показывает Ubuntu 24.04.5 LTS; отдельный distro snapshot на момент прежнего запуска не записан. [Сохранённое окружение эксперимента](../results/environment.json), [зависимости](../requirements.txt). NVIDIA GPU в описанных CPU-прогонах не использовался.

BLAS/OpenMP/MKL threads=1 в размерных прогонах. Время измеряет только `manager.update`, включает MNO и фильтр, не загрузку/выгрузку данных и внешний replay. Capture в baseline увеличивает накладные расходы; baseline wall time и время окон нельзя подменять друг другом. Частота CPU и внешняя нагрузка не фиксированы; выводы о стоимости описательные.

CLIPPER FetchContent в исходной сборке: pybind11 v2.9.2 (`914c06fb252b6cc3727d0eedab6736e88a3fcb01`), PMC `16af470353a784352760ec2deea25fa7ed602450`, SCS 3.2.3 (`f0c23340da03bcd663072dc4a90cf1aab8968c61`). Эти фиксации уже содержатся в upstream CMake; дополнительный код этих проектов не копируется. SHA исходного clipperpy `.so`: `128c80fcd807fac5cd6a7da667d687a2b70437985f9444e002f59bc0626b845f`.

## Обнаруженные несоответствия

При подготовке обнаружены расхождения, которые требуют пояснения, но не изменения экспериментальных чисел. Старые README и план описывают более широкий набор гипотез и прежние статусы; они сохранены в источнике, а [research_plan.md](../research_plan.md) относится к текущему исследованию. Для τ=8 из статьи выполнен только контроль временного фильтра на прежних кандидатах; release с τ=9 и область его воспроизведения описаны отдельно.

В метаданных разметки имя `partial_150` не соответствует числу назначенных ответов: их 159. Пустой `bundle_frozen.json` сохраняет флаги `manual_labels_received=false` и `relaxation_run=false`, поскольку относится к моменту заморозки до разметки. Эти исторические поля не используются как актуальный статус завершённого исследования.

В двух прежних диагностических текстах указан порог 0.5, хотя исполнявшийся основной код использовал release 0.75. Архив и корректирующие дополнения сохранены в источнике; численные результаты не пересчитывались. Новый отчёт использует 0.75, а отдельная неудачная probe с default 0.5 не включена в основной вывод. Кроме того, 3D-отбор не равен XY-поддержке алгоритма, а высокая уверенность разметчика не заменяет физические ID. Эти ограничения учитываются при интерпретации ручной проверки.
