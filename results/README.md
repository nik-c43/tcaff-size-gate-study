# Сохранённые результаты исследования

Результаты организованы в порядке исследовательской проверки: воспроизведение компонента TCAFF, ручная диагностика размерного допуска, абляция и модель наблюдений, проверка гипотезы о неопределённости, аудит сегментации и проверка рабочей гипотезы. [Таблица доказательств](evidence.csv) и её [JSON-версия](evidence.json) связывают каждую основную цифру с областью оценки, определением метрики, конфигурацией, источником и командой. Научная интерпретация приведена в [report.md](../report.md).

| Каталог | Содержимое |
|---|---|
| `baseline/` | Исходный release audit и lossless-сжатые вычисленные ошибки 4044 обновлений |
| `size_gate/` | Подбор α, поздние окна, холодный старт, подсчёт меток и компактные метрики 420 прогонов |
| `occlusion/` | 80 случаев идеальной модели и три синтетические маски |
| `diagnostics/` | Сводки дополнительных диагностик и прежние проверки целостности |
| `history/` | Проверки B0/B3 и MNO 4→16 с отличающимися протоколами |
| `uncertainty/` | Калибровка границы погрешности по самоконтролю трекера (отчёт, §7.2) |
| `segment_unit/` | Аудит сегментации FastSAM на 800 кадрах (§8) и проверка рабочей гипотезы на всей записи (§9) |
| `support/` | Гипотезы §10: диагностика T0, механизмы T2.0 и T3.0, сводки и трассы ошибок 15 прогонов G2/S2/R3, холодные старты, `aggregate.json` с правилами решения |
| `figures/publication/` | Научные PNG/SVG и сведения об их построении |

В компактных метриках каждого кадра сохранены поля `[step,time,accepted,[translation_m,yaw_deg] или null,correct,runtime_s,gt_available]`, а для прогона — параметры, исходный путь и хэш. Это позволяет повторно агрегировать вычисленные ошибки и сравнить конфигурации, сохранив связь с выполненным экспериментом. Повторная агрегация не является новым запуском алгоритма: исходные карты, GT-позы, FastSAM наблюдения и полные предложения остаются во внешнем snapshot.

В переносимых итоговых JSON изменены только локальные абсолютные пути в строковой метаинформации; численные поля сохранены. Это отражено в [инвентаризации](../docs/source_inventory.json). [Протокол проверок](../docs/validation.md) и [команды воспроизведения](../docs/reproduction.md) объясняют, какие результаты можно проверить автономно и для каких нужен внешний набор данных.
